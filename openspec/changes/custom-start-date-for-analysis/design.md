## Context

当前系统使用预定义的相对时间周期（`1m`, `3m`, `6m`, `1y`, `2y`, `3y`, `5y`）进行组合分析和优化。用户无法指定自定义的历史起始日期，限制了进行特定时间段回测的能力。

**现有实现**：
- `period_to_days()`: 将 period 字符串转换为天数
- `get_etf_nav_series()`: 根据天数计算起始日期，从数据库获取数据
- 前端通过 `timeRange` prop 传递预定义周期

**约束条件**：
- 数据库中已存储所有历史 NAV 数据，可按日期查询
- 需要向后兼容现有 period 参数
- API 改动需要保持 JSON 请求体格式兼容

## Goals / Non-Goals

**Goals:**
- 支持用户选择自定义起始日期进行组合分析和优化
- 保持与现有预定义周期的向后兼容
- 最小化后端改动范围

**Non-Goals:**
- 不支持自定义结束日期（固定为当前日期）
- 不支持选择特定日期区间的精确开始/结束日期选择器
- 不修改数据库 schema

## Decisions

### 决策 1: 前端日期选择模式

**方案 A**: 添加独立的日期输入框
- 用户可选择"预定义周期"或"自定义日期"模式
- 优点：UI 清晰，用户明确知道选择类型
- 缺点：需要额外的 UI 状态管理

**方案 B**: 替换现有周期选择为日期选择器
- 优点：UI 更简洁
- 缺点：用户失去快速选择预设周期的能力

**选择**：方案 A - 保留预定义周期下拉框，添加"自定义起始日期"复选框和日期输入框

### 决策 2: 后端日期参数格式

**方案 A**: ISO 8601 日期字符串（`2020-01-01`）
- 优点：标准格式，前端原生支持
- 缺点：需要修改 `period_to_days()` 的解析逻辑

**方案 B**: Unix 时间戳
- 优点：计算简单
- 缺点：不直观，调试困难

**选择**：方案 A - ISO 8601 日期字符串，与现有 `nav_date` 字段格式一致

### 决策 3: API 参数传递

**方案 A**: 修改请求体添加 `start_date` 字段
```json
{
  "etf_codes": [...],
  "start_date": "2020-01-01"
}
```

**方案 B**: 在 period 字段中支持日期前缀识别（如 `date:2020-01-01`）
- 优点：单一参数
- 缺点：解析逻辑复杂，容易出错

**选择**：方案 A - 显式 `start_date` 字段，更清晰易维护

## Risks / Trade-offs

[Risk] 用户选择早于任何 ETF 上市日期的起始日期  
→ [Mitigation] 后端检查数据可用性，返回友好错误信息

[Risk] 选择未来日期作为起始日期  
→ [Mitigation] 前端使用 date picker 的 max 属性限制为当前日期

[Risk] 跨度太短的时间段导致统计数据无意义  
→ [Mitigation] 后端设置最小天数阈值（如 30 天），不足时返回警告

## Migration Plan

1. **Phase 1 - 后端改动**
   - 修改 `period_to_days()` 识别 ISO 日期格式
   - 新增 `date_to_days()` 函数处理自定义日期
   - 修改 `get_etf_nav_series()` 支持可选 start_date 参数

2. **Phase 2 - API 改动**
   - 修改 `/portfolio/optimize` 端点接受 `start_date` 参数
   - 修改 `/portfolio/evaluate` 端点接受 `start_date` 参数
   - 修改 `/portfolio/compare` 端点接受 `start_date` 参数

3. **Phase 3 - 前端改动**
   - 在 OptimizerPanel 添加日期选择器 UI
   - 修改 `optimizePortfolio()` API 调用传递 start_date
   - 其他使用 period 的组件同步更新

4. **Phase 4 - 测试**
   - 验证预定义周期功能保持正常
   - 验证自定义日期功能正常工作
   - 验证边界条件处理

## Open Questions

1. 是否需要支持"结束日期"也可自定义？（当前设计仅支持起始日期）
2. 自定义日期范围是否需要保存在用户偏好设置中？
3. 是否需要提供"最近 N 个交易日"而非日历日的选项？
